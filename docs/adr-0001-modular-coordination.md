# ADR 0001: 通信と進捗管理をHarnessから独立させる

状態: 採用

## 要求

コントロールタワー・仕様・実装・レビューが、異なるモデルも使いながらメッセージ交換する。人間は通信の発生・本文・処理状況を確認できる。機能を順次追加・改修できる。

## 判断

1. 通信とタスクのルールはcore、Harnessへの接続はadapter、外部イベントはintegration、表示はHTTP observerへ分離する。
2. 通信本文と送信意図を先に保存し、配送結果を追記する。相手の受付と処理完了を区別する。
3. SQLiteのトランザクションを使い、現在の状態とイベントを同時に確定する。
4. 最初は単一プロセスを対象にする。別プロセス連携は認証付きの配送層を追加し、SQLiteを共有しない。
5. 配送途中の障害は結果不明として記録する。自動再送で重複処理を発生させない。
6. モデルの生成・選択はHarnessに任せる。プラグインは明示的に許可されたセッションだけを接続する。

## 帰結

Node.js標準機能だけでcoreと模擬デモを実行できる。公開Harnessパッケージの契約テストを分離して追加できる。DB保持期間や分散配送は追加作業になる。実モデルを含むエンドツーエンド運用と、モデルの判断の正しさは契約テストだけでは保証しない。
