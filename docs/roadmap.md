# 段階的な追加機能

## v0.1 — 今回の実装

- 設定済み・ロード済みのHarnessセッション間通信。
- 永続通信ログと読み取り専用の閲覧画面。
- 版番号・依存関係・SHA別の完了条件を持つタスク管理。
- 署名付きGitHub Webhookの受信とtowerへの通知。
- 模擬デモ、公開Harness APIの契約テスト、拡張ガイド。

## 次の優先候補

1. **実運用の配線**: 利用するHarness構成・モデルで4役を作成し、認証済みGitHubとつないだE2E検証。セッション作成・ID登録を補助するホスト機能。
2. **コード変更と進捗の対応付け**: PR・コミット・CI runをタスクに対応付け、古い通知を除外する。仕様版変更から影響タスクを提案する。
3. **処理待ちの可視化**: 未応答・停止・ブロッカー通知、最終活動時刻、担当者への再確認。人間が保留・再開・再割当できる操作。
4. **安全な並行実装**: worktree/ブランチの割当、変更範囲の衝突検知、PR経由のレビューと統合。
5. **別プロセス・別マシン**: 中央ブローカー、認証付きワーカー、ハートビート、相手側での冪等性、コールド再開。
6. **継続運用**: 保持期間、アーカイブ、DBマイグレーションテスト、プロジェクト別のアクセス制御、実コスト・予算管理。

各機能はアダプターや独立モジュールとして追加し、通信履歴の意味と既存データを保つ。優先順は実際の利用状況に応じて変更できる。
